| --- | --- |

## 环节一：AI 编程初体验 —— 最小命令行程序

### 提示词 1（第一版：生成最小程序）

```
请用 Python 写一个最小的命令行程序，运行时在终端输出一行：
Hello, AI 编程！
要求代码简洁，能直接在 Windows 的 Python 3 下运行。
```

**AI 生成结果**：一个仅含 `print("Hello, AI 编程！")` 的脚本。

**人工校验与修改**：
- 本地运行 `python hello_ai.py`，确认输出正确；
- 认为「只有一行 print」不足以体现工程化，于是提出微调需求（提示词 2）。

### 提示词 2（第二版：微调，加入参数与时间）

```
在这个程序基础上做两点小改进：
1）支持通过命令行参数 --name 传入姓名，输出 “Hello, 张三！欢迎使用 AI 编程。”；
2）另外打印当前运行时间。
请把问候语的构造抽成一个函数，方便后续测试。
```

**人工校验与修改**：
- 采用 `argparse` 解析参数，把问候语抽成 `build_greeting()` 函数（便于单元测试）；
- 本地分别运行无参数与带参数两种情形，均验证通过。

## 环节二：签到系统代码实现

### 提示词 3（生成 Flask 项目骨架）

```
用 Python + Flask 实现一个简单的课堂签到系统，要求：
1）首页有学号、姓名输入框，点击“签到”完成打卡；
2）同一学号同一天只能签到一次，重复签到要给出友好提示而不是报错；
3）要有一个“签到记录”页面，用表格展示全部签到明细；
4）用 SQLite 存储数据，数据库文件不要提交到 Git；
5）代码注释用中文。
```

**AI 生成结果**：单文件 `app.py`，含路由、模板字符串、SQLite 建表语句。

**人工校验与修改（重要）**：
1. **发现的问题**：AI 把所有逻辑塞进单文件，且用 `INSERT` 触发数据库唯一约束异常来「实现」防重复。
   → 人工改为**分层结构**：新增 `store.py` 作为数据访问层（`Store` 类 + `SCHEMA` 常量），
   `app.py` 只保留路由，模板拆到 `templates/`，样式拆到 `static/css/style.css`。
2. **发现的缺陷**：AI 版本没有校验空输入，学号为空会写入一条空记录。
   → 人工补充 `if not student_no or not name` 校验与错误提示。
3. **AI 的建议**：AI 建议使用 `Flask-SQLAlchemy`。
   → 人工判断本项目规模小、字段少，直接使用 `sqlite3` 标准库可减少依赖，**未采纳**。

### 提示词 4（功能扩展：防重复签到、迟到判定、CSV 导出）

```
在现有签到系统上增加三个功能：
1）签退：对当天已签到的学号补充签退时间，未签到不能签退，已签退不能重复签退；
2）迟到判定：当天签到时间晚于 09:00 的记为迟到，在记录页用不同颜色的标签显示；
3）把签到记录导出为 CSV 文件，注意要用 Excel 打开不乱码。
```

**人工校验与修改**：
- 采纳「CSV 加 UTF-8 BOM（`\ufeff`）」的做法，实测 Excel 打开中文正常；
- 人工把迟到阈值抽到 `Store.stats()` 中并加注释，方便以后改成可配置项；
- 人工补充 `409` 状态码语义（重复签到返回冲突而不是 500）。

### 提示词 5（报错排查）

```
运行 Flask 时报错：sqlite3.OperationalError: unable to open database file
项目目录结构是 signin-system/app.py 和 signin-system/store.py，
数据库想放到 signin-system/data/signin.db。请问原因和解决办法？
```

**AI 给出的诊断**：SQLite 不会自动创建**父目录**，`data/` 不存在时打开会失败；
应先 `os.makedirs(os.path.dirname(db_path), exist_ok=True)`。

**人工校验**：确认为真实原因，在 `Store.__init__` 中加入目录创建逻辑后问题解决。
（此问题也说明：AI 在首次生成骨架时遗漏了目录创建。）

## AI 使用总结

| 维度 | 结论 |
| --- | --- |
| AI 起到的作用 | 快速产出可运行的代码骨架、提供报错原因定位、给出前端样式与 CSV 编码等惯用做法 |
| 需要人工纠正的地方 | 架构分层（单文件 → 分层）、输入校验缺失、数据库父目录未创建、依赖过度引入 |
| 体会 | AI 显著降低了「从零到能跑」的成本，但**业务规则的正确性、异常分支的完备性**仍需人工把关；AI 倾向于给出「最短路径」实现，容易牺牲可维护性 |
